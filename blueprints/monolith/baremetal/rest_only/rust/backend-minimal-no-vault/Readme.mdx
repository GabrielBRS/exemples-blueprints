# backend-minimal-no-vault

Monolito REST **minimal** em Rust — tudo num `main.rs`, sobe em segundos.
Ponto de partida cru para um serviço novo; sem camadas, DI, traits ou testes.

**Slot no blueprints:** `monolith/baremetal/rest_only/rust/backend-minimal-no-vault`
**Stack:** Axum 0.8 · Tokio · SQLx (Postgres) · dotenv.
**Irmão industrial:** `backend-industrial-no-vault` (mesmo slot, em camadas
`handler → service → repository` com DI e testes) — o destino natural quando
este aqui crescer.

---

## Rodar

Pré-requisitos: Rust ≥ 1.80 e um Postgres acessível.

```bash
# Postgres rápido via Docker:
docker run --name pg-scaffold -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=scaffold -p 5432:5432 -d postgres:16

cp .env.example .env      # ajuste DATABASE_URL/PORT se precisar
cargo run                 # migrations rodam no boot; sobe em http://0.0.0.0:8080
```

Comandos de sempre: `cargo run` · `cargo build --release` · `cargo check`.

## Rotas

```bash
# health
curl http://localhost:8080/health
# {"status":"ok"}

# criar
curl -X POST http://localhost:8080/examples \
  -H 'Content-Type: application/json' \
  -d '{"name":"primeiro"}'

# listar
curl http://localhost:8080/examples
```

No Postman: método + URL; no POST use Body → raw → JSON com `{"name":"..."}`.

---

## O que tem aqui

Um único `src/main.rs` com: carga do `.env`, tracing, pool Postgres, migrations
embarcadas, três rotas (`/health`, `GET /examples`, `POST /examples`) com os
handlers falando SQLx direto, e um `AppError` enxuto (`400` para validação, `500`
para erro de banco, logado e não vazado).

Quando começar a repetir lógica, extraia `handlers/`, `services/` e
`repositories/` — e você chega no `backend-industrial-no-vault`.
